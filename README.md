# BsiCRM 1.1.0 — سالن زیبایی و مدیریت ارتباط با مشتری

سورس فرانت‌اند و بک‌اند بر اساس تصویر BsiCRM و گفتگوی اشتراکی، با رابط فارسی راست‌به‌چپ، تقویم شمسی و هویت سرمه‌ای/طلایی BsiCenter.

این تحویل، نسخه عملیاتی اولیه برای توسعه مرحله‌به‌مرحله است. دامنه پیاده‌سازی و بخش‌های باقی‌مانده صریحاً در [ماتریس نیازمندی‌ها](docs/REQUIREMENTS.fa.md) مشخص شده‌اند؛ آماده‌بودن برای بهره‌برداری واقعی باید با آزمون پذیرش روی سرور مقصد تأیید شود.

## تغییرات نسخه دوم

نوبت‌دهی با پیشنهاد زمان آزاد و جابه‌جایی دارای تاریخچه، برد پیگیری مشتری، یادداشت‌های تیمی، صفحه امنیت نشست‌ها، جستجوی سریع `Ctrl+K` و ظاهر تازه داشبورد اضافه شده‌اند. [جزئیات نسخه و راهنمای ارتقا](docs/RELEASE-1.1.fa.md) را ببینید.

برای ارتقا، `.env` و volume دیتابیس قبلی را نگه دارید و `docker compose up --build -d` را اجرا کنید. V2 یک migration افزایشی است و V1 تغییر نکرده است.

## اجرای سریع با Docker

پیش‌نیاز: Docker Desktop یا Docker Engine به همراه Compose و Python 3. در ویندوز، ترمینال را داخل پوشه `bsicrm` باز کنید.

```bash
python scripts/setup.py --demo
docker compose up --build -d
```

اسکریپت اول رمز مدیر را از شما می‌گیرد، کلید تصادفی JWT می‌سازد و `.env` را ایجاد می‌کند. گزینه `--demo` داده‌های ساختگی برای مشاهده داشبورد و ماژول‌ها اضافه می‌کند. برای پایگاه داده واقعی، بدون `--demo` اجرا کنید.

| مورد | مقدار |
|---|---|
| رابط محلی | http://localhost:3000 |
| رابط شبکه داخلی | http://172.31.13.30:3000 |
| API مستقیم | http://localhost:8080/api |
| سلامت بک‌اند | http://localhost:8080/actuator/health |
| نام کاربری اولیه | `admin` |
| رمز اولیه | رمز انتخاب‌شده در `setup.py` |
| PostgreSQL | دیتابیس `bsicrm`، کاربر `bt`، رمز `bt` |
| پورت PostgreSQL | `127.0.0.1:5432`؛ برای اتصال برنامه و ابزار مدیریت روی خود سرور |

IP ذکرشده باید متعلق به کامپیوتر میزبان باشد. پورت 3000 باید در فایروال شبکه داخلی قابل دسترسی باشد. آدرس API فرانت‌اند نسبی است؛ مرورگر درخواست‌های `/api` را به Next.js می‌فرستد و Next.js به بک‌اند پروکسی می‌کند. بنابراین لازم نیست IP در کد فرانت‌اند تغییر کند.

```bash
docker compose logs -f backend
docker compose ps
docker compose down
```

`docker compose down` داده را نگه می‌دارد. دستور `down -v` داده را پاک می‌کند و برای نگهداری محیط واقعی مناسب نیست.

## اجرای توسعه بدون Docker برای برنامه‌ها

Java 17+، Maven 3.9+، Node.js 22.9+ (پیشنهاد این پروژه: Node 24) و PostgreSQL 17 لازم است.

```bash
python scripts/setup.py --demo
docker compose up -d postgres
python scripts/run-backend.py
```

در ترمینال دیگر:

```bash
cd frontend
npm ci
npm run dev
```

اگر PostgreSQL از قبل نصب است، دیتابیس و نقش را بسازید و متغیر `DB_URL` را در `.env` مشخص کنید. مهاجرت‌ها با Flyway اجرا می‌شوند. حساب اجرای مهاجرت باید اجازه ساخت extension `btree_gist` را داشته باشد. در زیرساخت مدیریت‌شده، DBA می‌تواند ابتدا این extension را در همان دیتابیس فعال کند.

```sql
CREATE USER bt WITH PASSWORD 'bt';
CREATE DATABASE bsicrm OWNER bt;
-- Connect to bsicrm as an authorized database administrator:
CREATE EXTENSION IF NOT EXISTS btree_gist;
```

## PWA و HTTPS روی IP

در مرورگرهای پشتیبان، localhost زمینه امن محسوب می‌شود. روی IP شبکه داخلی، نصب و Service Worker به HTTPS با گواهی مورد اعتماد نیاز دارند. صرف تنظیم CORS این شرط مرورگر را تغییر نمی‌دهد.

```bash
docker compose -f compose.yml -f compose.https.yml up --build -d
docker compose cp caddy:/data/caddy/pki/authorities/local/root.crt bsicrm-local-root.crt
```

گواهی ریشه محلی Caddy را فقط روی دستگاه‌های تحت مدیریت خودتان و از همین سرور دریافت و در Trusted Root نصب کنید. سپس `https://172.31.13.30` را باز کنید. برای موبایل باید گواهی روی همان موبایل نیز مورد اعتماد باشد. در دامنه عمومی، Caddy را با نام دامنه و گواهی عمومی تنظیم کنید.

در حالت HTTPS، `COOKIE_SECURE=true` است. برای ورود در این حالت از آدرس HTTPS استفاده کنید؛ کوکی امن در HTTP روی IP ارسال نمی‌شود. تنظیمات پیش‌فرض CORS هر دو پروتکل و تمام پورت‌های localhost، 127.0.0.1 و IP خواسته‌شده را پوشش می‌دهند. برای هر دامنه دیگر، `CORS_ORIGINS` را صریح اضافه کنید.

PWA فقط فایل‌های استاتیک و صفحه قطع ارتباط را ذخیره می‌کند؛ پرونده‌ها، توکن‌ها، API و فاکتورهای اشتراکی کش نمی‌شوند. ثبت آفلاین عملیات مالی در این نسخه وجود ندارد.

## گردش کار پیشنهادی برای بررسی

1. با `admin` وارد شوید؛ در «تیم زیبایی» پرسنل و مهارت‌های مجاز را بررسی کنید.
2. مشتری جدید بسازید و رضایت تبلیغاتی را تنها در صورت وجود رضایت فعال کنید.
3. یک نوبت چندخدمتی ثبت کنید؛ همان زمان را برای همان متخصص دوباره رزرو کنید تا خطای تداخل را ببینید.
4. نوبت را تأیید و پذیرش کنید؛ در عملیات، هر خدمت را شروع و تکمیل کنید.
5. مراجعه را پایان دهید، فاکتور صادر کنید و بخشی را نقدی و بخشی را کارتخوان بپردازید.
6. ثبت امتیاز باشگاه، کمیسیون و گردش صندوق را بررسی کنید.
7. از کمپین یا ایونت استفاده کنید. آماده‌سازی کمپین در حالت پیش‌فرض پیام واقعی ارسال نمی‌کند.
8. نقش‌های منشی، مالی و آرایشگر را بسازید و محدودیت دسترسی را با هر حساب بررسی کنید.

## ساخت و آزمون

```bash
cd backend
mvn verify
cd ../frontend
npm ci
npm run build
```

روی یک دیتابیس آزمایشی مجزا و با سرویس پیامک غیرفعال:

```bash
python scripts/smoke.py --allow-test-writes
```

آزمون یکپارچه رکوردهای آزمایشی ایجاد می‌کند و عمداً داده واقعی را حذف نمی‌کند. رمز مدیر را به‌صورت مخفی می‌گیرد؛ برای CI از متغیر `BSICRM_TEST_PASSWORD` استفاده کنید. [گزارش اعتبارسنجی](docs/VALIDATION.md) دامنه آزمون‌های واقعاً اجراشده در زمان تحویل را مشخص می‌کند.

## ساختار پروژه

```text
backend/      Spring Boot، JDBC، امنیت، منطق دامنه و مهاجرت‌ها
frontend/     Next.js App Router، TypeScript، رابط RTL و PWA
scripts/      ساخت تنظیمات، اجرای محلی و تست یکپارچه
docs/         نیازمندی‌ها، معماری، API و قواعد مالی/امنیتی
compose.yml   اجرای PostgreSQL، بک‌اند و فرانت‌اند
```

دیتابیس دائمی در volume نگهداری می‌شود. برای پشتیبان‌گیری از `pg_dump` استفاده کنید و بازگردانی پشتیبان را روی دیتابیس مجزا آزمایش کنید. رمز PostgreSQL مطابق درخواست `bt` است؛ اتصال آن در Compose فقط روی loopback سرور منتشر شده است.
